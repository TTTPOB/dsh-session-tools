# ADR 0006：事件列表按锚点前缀适配输出预算

- 状态：Accepted（已采纳）
- 取代：[ADR 0002：展示预算与精确续读](<0002-local-reading-and-completeness.md#展示预算与精确续读>)中事件列表的整页超限处理。

## 背景

`session_event_list` 在固定的日志截止位置选取按 seq 排列的原始事件。这些事件称为本页锚点。紧凑视图按活动展示锚点和补读证据；同一活动可以跨多个不相邻的锚点。即使请求的 `limit` 很小，最终 JSON 也可能超过 `outputBytes`。继续调小 `limit` 不一定能解决单个活动过大的问题。

## 决策

1. 用当前页中能放进 `outputBytes` 的最长锚点前缀。针对每个候选前缀重新投影，证据中的页内锚点只包含前缀内的事件。补读记录仍可作为展示证据，不计入消费位置。按完整包装 JSON 的 UTF-8 字节数检查预算，包括视图、分页字段和提示。`metadata` 与 `compact` 使用同一分页规则。
2. 缩页返回 `page_truncated: { reason: "output_bytes", delivered: k, selected: n }`，其中 `n` 是预算检查前选中的锚点数，`k` 是实际交付的前缀长度。`notices` 提示用 `next_after_seq` 续页。即使原始页已到日志末尾，缩页也返回 `has_more: true`，且 `next_after_seq` 为第 `k` 个锚点的 seq。
3. 列表优先少交付几条锚点，保留活动预览。只在单锚点页仍超限时按既有顺序省略 `preview`、`arguments`、`result`、`error`、`meta` 等可选字段，保留身份、已知错误与定位信息。仍无法交付时明确报错，提示用 `view: "metadata"` 定位 seq，再用 `session_event_read` 读取单条原始事件。
4. 活动投影层独立给出单个活动的有界摘要：超预算时可以省略中间非必要 record，保留本页锚点、带错误的 record 和首尾 record，以 `records_omitted` 标明省略数量并标记 `truncated: true`。列表层仍以整个响应的字节数决定能提交的前缀。

## 理由与后果

假设活动 A 覆盖锚点 10 和 12，活动 B 覆盖锚点 11。如果这一页只装得下 A，可交付的连续前缀只有锚点 10，因此 `next_after_seq` 必须是 10。即使 A 的证据展示了 12，下一页仍从 11 继续；把游标设为 12 会跳过 B。同一活动可以出现在后续页中，但同一锚点只消费一次。

按活动数量截断不能保证上述顺序；先删整页预览会损失本可通过缩页保留的可读信息。按锚点前缀缩页允许调用方在相同筛选条件下继续浏览，而不需要猜测一个合适的 `limit`。
