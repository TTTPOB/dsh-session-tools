# dsh-session-tools

Independent DSH 0.1.7-rc.2 Cordis consumer for indexed session search and exact session browsing. This package does **not** contribute a bundle or replace a provider. It uses only `ctx.sessionQuery`; it never opens or decompresses session files. Built-in `session_search`, `session_event_search`, `session_event_read`, `session_trace`, and `session_event_trace` may already be registered by a profile: disable the built-in consumer before enabling these replacements. The seven tools here replace the old `agent_session_search`, `agent_session_list`, and `agent_session_read` entries from `dsh-session-search-pro`; do not register both consumer sets simultaneously.

## Scope and search

Each tool defaults to `scope: "project"`: the exact `exec.agent.session.header.cwd`, never the Host's cwd. Without a caller cwd, project scope fails; `scope: "all"` must be explicit and covers the **current sessionQuery provider's one DSH_HOME**, not multiple homes. The target is checked before cross-session reading; session search supplies the cwd filter **before** the provider query, not by trimming results afterward. Project traces hide out-of-project ancestor and descendant identities, and omit parent IDs in summary records. `all` enables cross-project reads/traces.

Both searches use **only** `searchSessions` and `searchEvents` and return indexed provider cursors; no scan fallback, `maxScan`, or `filterEvents` text search exists. FTS token semantics are not arbitrary substrings. A disabled, unsupported, or failed index raises the provider's original error category plus a message that **no logs were scanned**: report it to the user, do not scan logs as a workaround. Neither tool retries a failed provider request. `session_search` excludes its own session by default (`include_current: true` opts in). `session_event_search` on its own session excludes the executing `step/start` and later events. Cursor pages report only `items` and `nextCursor`; they never label page length a global total. Keep query and scope unchanged across cursor requests.

`session_list` lists metadata with `offset`/`nextOffset`; this is not a text search. `session_event_list` starts at seq 0 if `after_seq` is omitted, retains structural events, and returns an empty page with `nextAfterSeq: null` at EOF. Optional `event_types` filters explicitly; `view: "metadata"` omits preview, whereas default compact preview uses semantic documents from `filterEvents` **only for the known session's bounded page seq interval**. Empty text never removes a structural event. Follow the last returned `nextAfterSeq` until null.

`session_event_read` reads the raw event using `readEvent` and returns `dataBase64`, `format: "base64-encoded exact UTF-8 JSON byte slice"`, `offsetBytes`, `totalBytes`, and `nextOffsetBytes`. Decode base64 chunks to bytes and concatenate in offset order, **then** decode UTF-8 and parse JSON. Individual chunks can split a multibyte character and are not whole JSON. Continue at `nextOffsetBytes` until null. There is no fabricated full-text preview. Both trace tools call the public service and return complete, structured relationship data; if it cannot fit the configured byte budget they fail explicitly, never silently truncate links.

Config (Schemastery defaults): `pageSize: 30`, `maxPageSize: 100`, `previewChars: 240`, `outputBytes: 24576`. Each successful response is a native structured JSON object (`output.render` mirrors its JSON to the model). Output budgets count the complete UTF-8 JSON including metadata, enforce a minimum of 1024 bytes, and preserve continuation positions. In small budgets a single result that cannot fit fails rather than looping forever. `pageSize` cannot exceed `maxPageSize`.

## Build and handoff

Use Node 22.19+ or 24+, pnpm, `pnpm install --frozen-lockfile && pnpm check && pnpm pack`. The tarball contains built ESM, declarations, README and MIT license. Install the tarball **as a normal plugin dependency into every actual consuming profile**, then insert a `dsh-session-tools` row in the shared/global patch only after those installations resolve; do not enable via `dsh.bundle`. This repository deliberately has no real-profile edits, Host restart, push, or release. The installed profile must share Host Cordis/services peer identities; verify its actual resolution and effective configuration before activation.

After **the user has restarted and verified** the new tools, remove only the obsolete third-party dependency/bundle and task-specific temporary backup/worktree by their confirmed exact paths. Do not remove `session-search.db`, `session-search.db-wal`, `session-search.db-shm`, or any session storage: the existing SQLite provider/path is reused without rebuilding an index. Keep rollback files until post-restart verification succeeds. Development worktree and old plugin cleanup are separate from this package's activation.
